## Security implementation notes

The bullets below retain earlier verification details. For the current findings and project state, use the snapshot at the top of this file.

- On RR Capital, `account_balances` is a `security_invoker=true` view. Authenticated has SELECT but no INSERT/UPDATE; its underlying accounts and transactions retain RLS.
- `transaction_categories` grants authenticated SELECT/INSERT/UPDATE/DELETE with per-operation RLS policies requiring `owner_id = auth.uid()` (both `USING` and `WITH CHECK` for updates).
- `parties` and `obligation_payments` have RLS enabled, no policies, and no authenticated SELECT grant. Their current direct access is deny-by-default; application access must stay behind reviewed functions.
- The current local Perry draft revokes USAGE on `public` from `PUBLIC` and `perry_reader`, grants it explicitly to Supabase `anon`, `authenticated`, and `service_role`, revokes Perry access to the public wrapper, and grants only `private.personal_summary()`. The long-running local stack initially retained a direct public-schema grant; this is now covered by a passing regression. These migrations remain unapplied to hosted RR Capital; verify Data API, dashboard, and Supabase service-role flows after a reviewed migration before release.
- The 2026-10-01 RR Capital advisor snapshot listed eight RLS-enabled/no-policy tables, `pg_net` in `public`, and leaked-password protection disabled. `pg_net` was subsequently moved to `extensions` by hosted migration `20261002040958_place_pg_net_in_extensions_schema.sql`. The current advisor instead reports 12 informational RLS-enabled/no-policy notices; catalog checks confirm no anon/authenticated table grants on the affected private workflow tables and public `parties`, `obligation_payments`, and `profile_directory`. Leaked-password protection remains disabled.
- The v2 security advisor currently reports no lints; this is not proof of full authorization correctness.
- The Auth screen has no public registration flow; it offers password sign-in, Google sign-in, invitation password setup, and password recovery. Local Supabase config disables general, email, SMS, and anonymous signups and requires 12-character mixed-case/digit/symbol passwords with recent authentication for password changes; invitation and recovery password inputs now match the 12-character minimum. A public RR Capital Auth settings check reported `disable_signup: true`. Hosted HaveIBeenPwned/leaked-password protection is confirmed disabled by the advisor and is available only on Supabase Pro or above.
