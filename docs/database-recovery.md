# RR Capital database rebuild and recovery

The checked-in migration chain starts with `20260930000000_initial_schema.sql`, a schema-only snapshot of the pre-hardening RR Capital public schema. `supabase/New-SanitizedBaseline.ps1` replaces the legacy Telegram trigger body with a no-op before the baseline is written; the original private dump must never be committed. `20260930000001_auth_profile_trigger.sql` restores the profile-creation trigger on `auth.users`, which a public-only dump cannot contain.

For a **new** Supabase project, provision the normal Supabase auth and extension schemas, then apply every file in `supabase/migrations` in filename order. Do not load production user data into a test project. Keep project secrets, Telegram bot token, and webhook secret out of migrations and source control. Configure the Edge Function secrets separately and rotate the old embedded bot token before using Telegram.

For the **existing** RR Capital and Financial OS v2 projects, first compare live schema and migration history against this baseline. The baseline recreates tables/functions and must **not** be executed over an existing schema. Record the baseline and any already-applied hardening migrations as applied only after verifying their objects and definitions. For RR Capital, this reconciliation was completed on 2026-10-01. Applied versions include atomic/idempotent ledger and payment operations, balance validation, Telegram linking, receipt rate limits, encrypted per-user Gemini keys, write-boundary hardening, query-performance hardening, and creator notifications for request acceptance/decline. Two later grant-hardening migrations (20261001092558 and 20261001092901) restrict balance/category table privileges, hide private trigger functions from RPC, and explicitly revoke anonymous grants. The latest RR Capital migration `20261002030000_notify_creator_on_request_response.sql` adds minimal Telegram notices to the request creator after an obligation, EMI, or settlement is accepted or declined. The Edge Function was deployed first; the migration was then applied, and CLI migration history now matches with no pending migrations. The webhook URL and secret are present in Vault; their values were not read. Notification delivery depends on the creator having linked Telegram. No account identifier, amount, or other financial details are sent in the response alert.
